## 1 入力と差分の扱い

### 1.1 固定した決定

- 敵航空機・UFOなし。主砲20基＋大型機銃80基＝100基を六面へ配置する初期設計
- 全100基破壊で撃沈確定。隠れた船体HP戦や第二ボスなし
- 味方50機は自機込み総残機。初期同時8機、3秒復帰、予備枯渇時の僚機引継ぎ
- 弾薬の総補給は無限、MG288／機関砲96、両空で6秒装填。僚機も装填
- **D01確定**: 爆弾・魚雷なし。機能・UI・Z／X割当・設定・ガイド・説明を持ち込まない
- 砲台破壊＋編隊の実損傷＋時間1項目から、自機／僚機損失と合算命中率低下を減点
- 操縦・設定・UI体系は固定参照を基準とし、ゲーム固有の状態・採点・母艦戦を分離する

R／A／U／I／Dの番号はすべて上記固定版要件の番号。本書で条件を弱めたり、要件と別の数値を第二正本にしたりしない。初期設計値を変更する場合は、先に要件差分と影響A番号を提案し、計画の基準SHAを更新して再点検する。

### 3.1 識別子と戦闘イベント

- 作戦IDは再出撃ごとに更新。機体トークンは作戦内50個、出撃枠とは別
- 砲台IDは固定100個で、面・種類を持つ。弾IDは作戦内で一意、再利用プールindexとは別
- 射手の種別と操作担当は発射時に弾へ保存。射手の死亡・引継ぎで飛行中の弾を破棄しない
- DamageEventは作戦、弾、射手、対象ID／世代、tick内接触時刻、計算損傷mHP、実損傷mHPを保持
- DestroyEventは対象IDごと1回。弾の多重colliderは対象正規IDへ集約する
- scoreはこれらの確定イベントの通算から算出し、HUDと結果で別集計をしない

### 3.2 固定tickの順序

1. 非active状態なら戦闘の更新をしない。activeなら当該tickの受理済み入力を1回取り出す
2. 既存予約・装填・AI・砲台時計について、当該tickで期限に達したものを識別する。前tickからの時計を二度減らさない
3. 当該tick開始姿勢から操縦とAIを計算し、機体移動軌跡と砲台の有限旋回を求める。発射予定は要求として時刻付きキューへ入れ、この時点では弾倉やNを消費しない
4. 既存弾／機体の連続接触と新規発射要求を同じ時系列で解決する。同一時刻は接触・損傷・破壊を発射要求より先に処理し、接触同士は攻撃ID→対象ID、発射要求同士は射手ID→武器種→要求IDの固定順とする。新規弾の寿命末尾を切り詰めた接触候補もキューへ追加する
5. 実生成の直前に射手の生存、作戦、弾倉、射界／遮蔽／予約を再検査し、既に破壊された射手の要求は取り消す。射界／遮蔽／予約は当該兵装に要求される条件だけへ適用し、Normalの空や壁への手動射撃は妨げず、実生成した自機弾をNへ数える。生成できた弾だけ弾倉を減らし、自機所属だけNを増やす。接触で実損傷・破壊と自機所属弾のHを一度だけ確定する。被破壊前に実生成した正当な弾は寿命まで有効とする
6. R25に従い全破壊後の終了条件を1回評価。味方0を先、次に砲台0。終端なら結果を凍結して予約・弾の後続更新をしない
7. 継続中だけ空き枠へ自機優先でR→Qを予約し、期限済みQ→Aを安全な候補へ出撃。新機体の初回戦闘更新は次tickとする
8. Q→A後に操作所有を再評価し、180tick経過後の僚機引継ぎをtick末尾で確定する
9. read-only snapshotと一意イベントを画面・音へ渡し、次tickへ進む

詳細な内部順序を変更するときは、同tick破壊／発射／復帰の境界fixtureを先に更新し、要件の相討ち・予告取消し・有限残機を維持する。フレームレートで順序を変えない。

## 4 実装段階

### P0 基準と実施条件を固定する

開始条件: 実装の別途指示があり、要件の採用版と作業対象が明確であること。文書PR作成だけでは開始しない。

作業:

1. 対象の現main／未処理差分を読取り、文書段階後の変更を失わないよう比較する。固定要件SHAとD01を再確認
2. 移行候補の公開ソース・NOTICEをファイル単位で調査し、来歴台帳と非採用一覧を作る
3. ルール版、mode、seed、物理単位、入力記録形式、fixtureの通常／合成区分を決める
4. テスト・ビルド環境の採用版をlockfileと共に記録する。新しい秘密情報・認証・DB接続を求めない
5. 性能対象のmanifestを測定前に固定する。PCは実機のCPU/GPU/RAM/OS/ブラウザ、1,366×768 CSS px、DPR1、標準画質。モバイルはiPhone 17 Pro/Safari候補、393×852 CSS pxを基準に実viewport/DPRを記録し、描画DPR上限2を初期画質案にする
6. 実機が確保できなければ性能の実機欄を未検証とし、模擬値で合格させない。別機種を採る場合は測定前に同等性・変更理由と対象要件を明記する

完了証拠: 基準SHA一覧、要件blob一致、移行分類、依存版、測定manifest、実行できる検査／できない検査一覧。A24、A26の採用境界を確認する。

### P1 操縦と最小画面を移す

共通の機体、飛行、カメラ、相対ドラッグ、キー設定、タッチ設定、dialog焦点を移し、母艦の仮外形を置いた最小ローカル画面を作る。共通部分の変更差分を記録し、R30／R61–R64を先に確立する。爆弾／魚雷とZ／X、ランキング、元作固有missionを依存ごと持ち込まない。

ホーム・準備・戦闘・停止・結果の状態だけを先に接続する。戦闘用の結果はこの段階では仮接続と明記し、全滅クリア実証と呼ばない。初期化／disposeと停止を共通入口へ集約し、音初期OFFを維持する。

完了条件: 操縦の共通値とカメラの来歴が比較可能。設定の保存／取消し／未来形式／途中失敗、キー9操作、タッチ4/1、入力保持解除、フォーカス、非表示停止が最小シーンで検証される。A07の操縦部分、A16、A17、A21、A26。

### P2 母艦と砲台配置の幾何を作る

依存: P1。

母艦の1,200×600×240m、中心高度1,000mを基に、共通意匠を手続き形状へ落とす。前後・左右・上下面を定義し、20主砲／80機銃を指定の面別件数で固定データ化する。初期・復帰候補は全砲口から射程＋100m、機体間30mの条件で生成する。

全100基のID・種別・3軸・可動範囲・HP・砲座／砲口を検査し、各砲台の外向き射線と300m進入区間、六面を結ぶ外周経由点を作る。描画の穴・装甲張出し・低い破壊残骸とcollisionが一致するよう、同じ配置データを使う。母艦全体を巨大AABBひとつだけで判定しない。静的形状は空間分割で候補を絞り、最近接sweepで最終判定する。

完了条件: 全100基に到達可能性データがあり、上下面・前後の通常カメラ画像を確認。銃弾・機体・敵射線の遮蔽一致、反対面貫通なし、初期点安全、基数と総HP24,000一致。A02–A04の形状部分。

停止条件: 1基でも合法な攻撃経路がない場合はP3以降でHPを直接削って通過せず、配置と外形を修正する。

### P3 有限残機と味方銃撃と得点を作る

依存: P2。

50トークンの保存則、3秒復帰、予約と出撃枠、予備枯渇時の操作引継ぎ、作戦終端を先に実装する。敵攻撃なしの状態fixtureで自機と僚機の破壊／予約境界を検査する。これを勝利経路証拠と呼ばない。

自機と僚機へ288/96の弾倉、6秒装填、5/15・17/57tickの各2発射、弾速、90tick寿命、距離減衰、1/1,000HP整数損傷を接続する。各射手は固定容量から2枠を一括予約し、全射手の弾倉は実生成時だけ減らす。Nは発射時に自機所属の実弾だけを数え、僚機弾はN/Hに含めない。引継ぎ前後に旧自機弾と旧僚機弾が着弾するfixtureで発射時所属を確認する。味方銃弾256のうち64を自機用として確保する。

砲台HP・損傷段階・破壊集合を正本にして、K／Damage／P／W／Hを計算する。R50の成分と160,000点例、N0、負点、味方とどめ、overkill、終端の未着弾を単体で固定する。結果保存は本作だけのキーでモード／ルール版を分ける。

完了条件: A05–A08、A13–A15の論理fixtureが通り、N/H・HP・トークン・弾倉の全tick不変条件を記録できる。A01の全滅条件と相討ち優先を検証する。

### P4 敵砲台と僚機AIを接続する

依存: P3。

主砲・機銃の攻撃枠を4/12、同標的予約を1/3とし、事前追尾→角誤差1度内→固定予告→射撃→装填の状態機械を作る。事前追尾2秒失敗、射界／遮蔽／標的破壊による取消し、発射後の装填、枠の解放、待機tickとID順の公平な選択を実装する。

主砲は予告1秒を含む等速迎撃点、400m/sの非誘導弾、直撃24HPまたは遮蔽あり20m爆風最大12HP。機銃は0.3秒予告、650m/s、F〜F+54の10発、120tick装填。砲台破壊後の新規発射は止め、既発射は寿命まで有効。作戦終端だけは全弾を凍結する。

僚機は全六面を担当できる外周経由点、同一砲台最大2機、30tickごとの再評価、破壊・不達時の解放を実装する。射撃・HP・位置は通常の飛行と実弾から更新し、AIだけの必中・壁抜け・直接HP減算を入れない。Normalの自機誤射と保護弾の遮蔽を検査する。

完了条件: A09–A12。上面／下面／側面それぞれで主砲と機銃を通常入力で回避する映像、最後の下面1基へ僚機が経路を取り直す証拠、画面外で論理が止まらない記録。未調整の敵攻撃を無効化して本番勝利を合格させない。

完了条件: A16–A18、A20–A21の全画面経路。短い画面、200%文字、横画面、safe-area、アドレスバー変化でも出撃／保存／閉じる／再出撃へ到達できる。手動で画像と焦点遷移を確認する。

## 5 検査設計

### 5.2 ブラウザの通常入力経路

ChromiumとWebKitの模擬条件を使い、実機とは別の証拠にする。単なるゲーム内部関数の直接呼出しではなく、製品の入力面・キー・ボタンを通す。

1. ホーム→モード選択→操作説明→閉じる→出撃。準備が完了して操作可能となる最初の論理tickから時計が始まる。出撃後に無入力でも時計と戦闘が進み、最初の操縦入力まで開始を遅らせない
2. EasyとNormalのタッチ／PC入力、同時操縦＋射撃／宙返り、保持中のblur/cancel/lostcapture/resize
3. 停止→設定→保存／取消し→説明→閉じるで停止維持。Enterを停止へ割当ててもホームの出撃操作を奪わない
4. 通常飛行で六面へ接近し、母艦を回り込む。上面の自機射線から船体で遮蔽された反対面へ直接命中しない。僚機が通常の飛行で下面へ回り込み破壊することは合法であり、自機が上面にいるという理由で全滅結果を失敗扱いしない
5. 実弾でHPを失い自機破壊→復帰。入力とカメラの旧機体所有を解放し、戦闘時計は待機中も進む
6. 別の状態境界fixtureで予備枯渇→僚機引継ぎを確認。これを通常全滅クリアの証拠へ流用しない
7. Easy／Normalの固定入力経路で100基全破壊、確定時刻→演出スキップ／待機→同じ結果
8. 結果→再出撃10回、ホーム往復、二重クリック、非表示復帰、WebGL喪失から案内と明示再開

各経路はseed、入力列、モード、head、ブラウザ版、viewport、終了理由、原票と画像を残す。検査操縦が内部位置を観測していても、出力は製品が受理する通常入力だけとし、実人間の難易度・操作感の合格と区別する。

### 5.3 負荷と資源

通常最大負荷の開始条件は要件R82どおり。100基生存・8機出撃・主砲4／機銃12の合法攻撃機会を含むseedと、複数面を通過する入力を記録する。30秒ウォームアップ後に180秒測定し、破壊によって負荷が減った区間は生存数と一緒に示す。全180秒を上限負荷として維持する別fixtureが必要なときは、不死化／HP復元等の介入を明示した合成負荷とし、通常クリアの証拠へ使わない。

味方弾は自機32発/秒×1.5秒で48発、僚機7機は概算で7×(120/17＋120/57)×1.5≒96.2発の生存上限目安となる。64自機予約と256全体容量に対し、斉射端点・開始位相を含む離散tick検査で余裕を確認する。概算だけで容量合格にしない。敵は砲台が入れ替わる攻撃枠の解放条件を含め、機銃256／主砲16で通常発射不成立0を確認する。

意図的にプールを満杯にする異常fixtureでは、部分斉射なし、N／弾倉不変、敵の1tick延期と残り予定の同量延期、60tick連続失敗で異常停止を確認する。通常性能不合格を弾の消去・敵の間引きで隠さない。

15分と10再出撃では、最大弾数、DOM、リスナ、AudioContext／音源、WebGL geometry／texture／material、JS heapのウォームアップ後推移を測る。GCの瞬間値だけで漏れを断定せず、各作戦終了後の安定点と固定資源カウンタを比較する。停止中は時計・予約・弾数が不変であることを記録する。

### 5.4 再現性と許容差

受理入力、seed、初期状態を固定し、30／60／120Hz描画で論理snapshot hashと最終tick・HPmilli・K・Damage・P・W・N・Hを一致させる。乱数は作戦seedだけから取り、粒子用乱数を戦闘乱数へ混ぜない。描画補間の小数差やスクリーンショット画素差は別の比較で、論理差を画素許容差に埋めない。2秒gapや非表示は明示停止として記録し、未処理時間を一括dtへ流し込まない。
